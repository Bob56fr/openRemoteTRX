Bêta-test de l'application : envoyer le journal d'erreurs du téléphone

Quand l'installation échoue (« Une erreur s'est produite », sans plus de détail) ou que l'application se ferme toute seule, le Play Store ne nous dit rien. La vraie cause est écrite dans le journal de votre téléphone. Cette page explique comment le récupérer et nous l'envoyer.

Le journal contient des informations personnelles (noms de réseaux Wi-Fi, comptes, autres applications). Ne le publiez jamais dans un forum ni dans un ticket public : envoyez-le seulement en répondant à l'e-mail qui vous a invité au test.

Deux méthodes :

  • Méthode 1, sans ordinateur : le « rapport de bug » d'Android. Simple, mais gros fichier (10 à 50 Mo) et très complet.
  • Méthode 2, avec un ordinateur (Windows, macOS ou Linux) et un câble USB : un petit fichier texte qui ne garde que les lignes utiles. Préférée si vous pouvez.

Étape commune : activer les options pour les développeurs

  1. Ouvrez Paramètres → À propos du téléphone. Samsung : puis Informations sur le logiciel.
  2. Appuyez 7 fois sur Numéro de version (ou « Numéro de build »). Saisissez le code du téléphone si demandé. Le message « Mode développeur activé » apparaît.
  3. Un nouveau menu Options pour les développeurs apparaît dans Paramètres (Samsung : tout en bas ; autres marques : dans Système).

Rien n'est modifié sur le téléphone : ce menu reste simplement visible. Vous pourrez le désactiver à la fin (voir plus bas).

Méthode 1 : rapport de bug, sans ordinateur

  1. Reproduisez le problème (lancez l'installation qui échoue, ou l'action qui ferme l'application), puis faites le rapport tout de suite : le journal ne garde que les dernières minutes.
  2. Paramètres → Options pour les développeurs → Rapport de bug (ou « Créer un rapport de bug ») → Rapport interactif → Signaler.
  3. Attendez une à trois minutes : une notification « Rapport de bug … prêt » apparaît.
  4. Appuyez sur la notification, choisissez votre messagerie, et envoyez le fichier .zip en réponse à l'e-mail d'invitation. S'il est trop gros pour la messagerie, passez par un service de partage de fichiers (lien privé).

Méthode 2 : journal ciblé, avec un ordinateur

1. Installer l'outil adb (une seule fois)

  1. Téléchargez les SDK Platform-Tools de Google pour votre système : developer.android.com/tools/releases/platform-tools.
  2. Décompressez le fichier : vous obtenez un dossier platform-tools (par exemple dans Téléchargements). Il n'y a rien à installer.
  3. Ouvrez un terminal dans ce dossier :
    • Windows : ouvrez le dossier dans l'Explorateur, clic droit dans un espace vide → Ouvrir dans le terminal (ou Maj + clic droit → « Ouvrir la fenêtre PowerShell ici »).
    • macOS : Terminal, tapez cd puis glissez le dossier dans la fenêtre, puis Entrée.
    • Linux : clic droit dans le dossier → « Ouvrir un terminal ici ».

Dans les commandes ci-dessous, tapez .\adb sous Windows et ./adb sous macOS et Linux.

2. Brancher le téléphone

  1. Sur le téléphone : Options pour les développeurs → activez Débogage USB.
  2. Branchez le téléphone à l'ordinateur avec un câble USB de données (certains câbles ne font que charger).
  3. Dans le terminal : 
    .\adb devices
  4. Sur le téléphone, une fenêtre demande « Autoriser le débogage USB ? » : cochez « Toujours autoriser depuis cet ordinateur » puis Autoriser.
  5. Relancez .\adb devices : une ligne se termine par device. Si elle se termine par unauthorized, déverrouillez le téléphone et acceptez la fenêtre ; si rien n'apparaît, changez de câble ou de prise USB.

3. Enregistrer le problème

  1. Videz le journal pour ne garder que le problème : 
    .\adb logcat -c
  2. Reproduisez le problème sur le téléphone (installation depuis le Play Store, ou l'action qui ferme l'application).
  3. Juste après, enregistrez les lignes utiles dans un fichier :

    Windows :

    .\adb logcat -d | findstr /i "Finsky PackageInstaller openremotetrx AndroidRuntime webrtc" > journal-openremotetrx.txt

    macOS et Linux :

    ./adb logcat -d | grep -iE "finsky|packageinstaller|openremotetrx|androidruntime|webrtc" > journal-openremotetrx.txt
  4. Le fichier journal-openremotetrx.txt est dans le dossier platform-tools. Ouvrez-le pour vérifier qu'il n'est pas vide, puis envoyez-le en réponse à l'e-mail d'invitation.

Si nous vous demandons le journal complet (plus gros, avec plus d'informations personnelles) :

.\adb logcat -d > journal-complet.txt

Ce qu'il faut écrire avec le fichier

  • Le modèle du téléphone et sa version d'Android (Paramètres → À propos du téléphone).
  • La version de l'application si elle est installée (Paramètres → Applications → openRemoteTRX, en bas de la page).
  • L'heure du problème, à la minute près.
  • Ce que vous faisiez et le message affiché (une capture d'écran aide beaucoup).

Après le test

  • Désactivez le Débogage USB : un téléphone qui l'a activé peut être lu par un ordinateur autorisé.
  • Pour cacher le menu, désactivez l'interrupteur en haut de Options pour les développeurs.
  • Supprimez les fichiers de journal de l'ordinateur et de la messagerie une fois envoyés.

Les journaux reçus servent uniquement à corriger l'application et sont supprimés ensuite. Règles de confidentialité de l'application : confidentialité.
