TRX Console: user manual

TRX distant version 0.130.0

Language: Français · English · Deutsch · Español

TRX Console is the control panel of the TRX distant station, on the PC (or Raspberry Pi) connected to the transceiver. It is used to install and configure the station, start it, test it, update it and troubleshoot it. Open it from the applications menu ("TRX Console") or by typing trx-console in a terminal.

The menus are grouped by theme (Station, Troubleshooting and tests, Configuration, Access, Features, Updates): type the theme number then the menu number, or both at once, for example 4.1 to pair a phone. 0 changes the console language (français, English, Deutsch, Español).

Not sure about a menu? Type h followed by its number (for example h 4.1): without running anything, the console shows what the menu is for, when to use it and what it changes (the texts of this page).

It never transmits on its own: the only menus that can put the transceiver into transmit are the full test (menu 2.2, with confirmation at each step) and, of course, the station once started, controlled from the web page.

First deployment? Follow the steps below in order. Station already in service? Go straight to the menu reference. Helping with debugging? See the "Advanced troubleshooting" part.

First deployment, step by step

  1. Install the software

    On a Debian 12 or 13 PC with a desktop: unzip the package trx-remote-debian-X.Y.Z.zip into Downloads, open a terminal in the resulting folder and type:

    sudo bash install.sh

    Your session password is asked (nothing is shown while you type: this is normal). At the end, log out then log in again so that the new rights take effect.

    Coming from a Windows station? Put its station.toml file next to install.sh before starting the installation: accounts, bands and alerts will be carried over.

  2. Configure the station (menu 3.1)

    On first launch, TRX Console offers the wizard. It asks, in order: the transceiver model (Hamlib list), the CAT serial port, the PTT method, the sound cards (receive and transmit), the bands allowed for transmission, network access and the first account (username and password for the web page).

    The transceiver is queried read-only during the wizard: no transmission. Nothing is saved if you give up halfway.

  3. Check (menu 2.1)

    The diagnostic reviews everything without changing anything. Each line is OK, to watch or failed, with what to do. Fix the failures before going further (menu 3.2 to adjust the configuration, or run the wizard again).

  4. Test the transceiver (menu 2.2)

    First of all, the transceiver sound card must not be the PC's default sound device: on Debian, Settings > Sound, choose the PC speakers as output and its microphone as input (on Windows, Settings > System > Sound). Otherwise the desktop holds the card and its sounds go to the transceiver.

    Start with the receive-only test (choice 1): CAT link, received audio, frequency and mode changes, filter widths, spectrum. Only then does the full test (choice 2) check transmission: dummy load required, reduced power, confirmation asked at each step. The station is stopped during the test.

  5. Start (menu 1.1) and connect

    Menu 1.1 starts the station; run a diagnostic again (menu 2.1) a few seconds later. On the phone or another PC on the same network, open https://<adresse-de-la-station>:8443 and log in with the account created by the wizard. For access from outside, see the project's "Remote access" documentation.

The console menus

The main menu shows the themes: type the number of a theme then the number of one of its menus, or both at once (6.3); r goes back to the main menu, 0 changes the language, q quits. The old numbers 10 to 24 (single level, up to version 0.125.0) are still accepted for a while: the console gives the new one. Answers to questions (oui, non, OUI, EMETTRE...) ignore upper/lower case and accents. Password: the menu asks for your session password (sudo).

1) Station

1.1

Start or restart the station

What it is for
Starts (or restarts) the station: rigctld, gateway, supervisor.
When
After configuration, after a change, or if the web page no longer responds.
What it changes
The state of the services. The transceiver is always set back to receive at startup.
Rights
session password asked
1.2

Stop the station

What it is for
Stops the station.
When
Before plugging or unplugging the transceiver or the audio interface, or to use other software on the transceiver.
What it changes
The state of the services. The transceiver stays in receive.
Rights
session password asked
1.3

Dashboard (frequency, transmission, services)

What it is for
Live dashboard, in the terminal: frequency, mode, transmit or receive, connected clients, services, hardware, audio, log.
When
To watch the station on site, or during a test.
What it changes
Nothing, except one key: STOP TX forces receive. The dashboard can never make the transceiver transmit.
Rights
no
1.4

Station log

What it is for
Shows the last 80 lines of the station services log.
When
When the diagnostic reports a failed service, or to understand why a transmission was cut.
What it changes
Nothing.
Rights
session password asked

Going further

Full log: journalctl -u trx-gateway -u trx-supervisor -u rigctld --since "1 hour ago".

1.5

Leave safe mode

What it is for
Leaves safe mode. The supervisor puts the station into it after repeated failures: transceiver in receive, access cut.
When
Only after finding and fixing the cause (menus 2.1 and 1.4).
What it changes
Clears the stored safe mode and restarts the station.
Rights
session password asked

Going further

Safe mode survives restarts and fixes: it must be lifted explicitly here.

2) Troubleshooting and tests

2.1

Full diagnostic

What it is for
Full check of the station, read-only: system, software, configuration, hardware (serial ports, sound cards), services, HF spectrum, DX Cluster, network access and updates. At the end, three "Station modes" lines: Breizh Audio Box (enabled or not, link state), visitor listening (open or closed, maximum number) and visitor accounts (nickname, disabled, expired), without any secret.
When
After installation, after every change, and as a first reflex whenever something is wrong.
What it changes
Nothing. No command to the transceiver, no transmission.
Rights
no

Going further

Same result without the menu: trx-console --diagnostic (non-zero exit code on failure, usable in a script).

2.2

Transceiver test (CAT, audio, PTT)

What it is for
Guided test of the real transceiver. Choice 1: receive only (CAT, received audio, tuning, filter widths, spectrum display). Choice 2: the same, then transmission.
When
After the wizard, after changing a cable or audio interface, or to qualify a new transceiver.
What it changes
Nothing in the configuration. Choice 2 makes the transceiver transmit: dummy load, reduced power, confirmation (type EMETTRE) at each step. The station is stopped during the test.
Rights
session password asked

Going further

The final summary of the test is shown on screen: copy it into your help request. Typed answers ignore upper/lower case and accents ("emettre", "Émettre" and "EMETTRE" are accepted).

2.3

Troubleshooting report (zip on the Desktop)

What it is for
Creates a troubleshooting report (zip file on the Desktop): diagnostic, logs, configuration without any password, versions, detected hardware, reports sent from the page, station identifier.
When
To ask for help: attach this zip to your request.
What it changes
Nothing (a file is created on the Desktop).
Rights
no

Going further

Without the menu: trx-console --rapport. The report's station.toml file has its secrets masked; you may still check its content before sending it if you wish.

2.4

Network quality (links, dropouts, statistics, export, erase)

What it is for
Shows the quality of the links between the station and the connected phones or browsers: for each one, the state (good, fair, weak, dropout), the network type, the loss and the round-trip time; the state of the station probes towards the router and the Internet; the last dropout with its probable segment; and the "VPN profile probably shared" warning when two devices seem to use the same VPN profile. Here you read the summary of the last 24 hours or the last 30 days (dropouts, duration, segments, most affected hours, per network), create an anonymous export on the Desktop for the development team, and can erase everything.
When
When the link often drops (in the car, on 4G, through a VPN), to find out whether it is the phone, the mobile network, the tunnel, the router or the station; before asking for help (export).
What it changes
Nothing, except "Erase everything" (confirm by typing EFFACER): the station's network history (dropouts, statistics, devices seen). The indicator thresholds chosen in the page or the app are kept. The export is a zip file on the Desktop.
Rights
session password asked

Going further

The station sends a one-second heartbeat to each connected client and waits for its echo; three heartbeats without an answer make a dropout. After each dropout, it combines its own probes (router, Internet, ping or else TCP), the measurements sent by the client (including HTTPS access to the station during the dropout) and the regularity of the dropouts to tell which segment probably failed; it is a probability, never a certainty. Two devices on the same VPN profile steal the link from each other every 15 to 30 s: one profile per device. The probe only measures: it never acts on transmission. Files: netprobe folder in the state folder (7-day log, 30-day dropouts and statistics). Same summary on the command line: trx-netreport (--jours 30, --export FICHIER). Settings: [netprobe] section of station.toml (menu 3.2). "Erase everything" asks for sudo: the files belong to the station account. Details: docs/netprobe-cahier-des-charges.md.

2.5

Last antenna SWR measurement (read-only)

What it is for
Shows the last antenna SWR measurement stored on the station: date, power, mode, range, and the SWR of each point with a small bar ("HIGH" above 2), the best point and any transceiver settings that may not have been restored. Read-only: the console never starts a measurement (a tool can only cut a transmission); the measurement is started from the page or the app.
When
To find a measurement made remotely, compare it with a new one, or check that a transceiver setting was properly restored after an interrupted measurement.
What it changes
Nothing.
Rights
no

Going further

File read: swr.json in the station state folder (last choices of each account, SWR reading time calibrated per transceiver model, last measurement). Station settings: [swr] section of station.toml (menu 3.2: enabled, power ceiling max_power_pct, max_points, point_tx_max_s). Details: docs/tos-cahier-des-charges.md.

2.6

Expert menu (automatic software tests)

What it is for
Expert menu: runs the whole automatic software test suite on the station.
When
To help with debugging, or to check that an installation is healthy.
What it changes
Nothing. The tests use a simulated transceiver: no command to the real transceiver, no transmission. The station is stopped during the tests (7 to 10 minutes on a recent PC, 30 minutes or more on a small PC) then restarted on request.
Rights
session password asked

Going further

The result is saved on the Desktop (trx-remote-tests-AAAAMMJJ-HHMM.txt): send this file if tests fail. The test tool (pytest) is installed on first use (Internet required).

Dots are shown as the tests progress; with nothing new for a minute, the console reminds you that the tests are still running. A test truly stuck for 10 minutes shows the stack of its threads: that is what to send (Ctrl+C stops the tests).

3) Configuration

3.1

Configuration wizard

What it is for
Configuration wizard: transceiver, ports, PTT, sound cards, allowed bands, network access, accounts. Writes station.toml.
When
On first deployment, or to start over (new transceiver, audio interface or PC).
What it changes
station.toml (only if you go to the end). The station is stopped during the wizard then restarted on request.
Rights
session password asked

Going further

The transceiver is only queried read-only. A configuration imported from an old station (station.import.toml) is used as a starting point.

When a transceiver is added, the wizard asks whether replay of recordings is allowed (app: record the received audio then send it back on transmit, duration limited to the maximum transmit time minus 5 s). Default answer: no. Retransmitting a station's signal to third parties is generally forbidden in the amateur service: accept only if you need it and under your own responsibility ([safety] allow_replay).

3.2

Edit the configuration (station.toml)

What it is for
Edits station.toml in the nano editor, on a copy.
When
For a specific setting without running the whole wizard again.
What it changes
station.toml, only if the copy is valid: it is checked, the differences are shown, a confirmation is asked and the old version is kept alongside. An invalid configuration is never written.
Rights
session password asked

Going further

In nano: Ctrl+O then Enter to save, Ctrl+X to quit. Backup copies are named station.toml.avant-modification-AAAAMMJJ-HHMMSS.

Reference of ALL settings (role, default value, limits, safety, menu that changes them): https://bob56fr.github.io/openRemoteTRX/station-toml/, also on the rf-diy.com site.

3.3

Transceiver profiles (several rigs: save, load, delete)

What it is for
Transceiver profiles, for those who use several rigs in turn: save the configuration of the transceiver in service under a name ("IC-7300 home"), reload it later, or delete a profile. The profile in service is marked in the list.
When
After configuring and testing a transceiver (menus 3.1 and 2.2): save it. To change transceiver: plug it in, load its profile, and the station restarts with it.
What it changes
Loading a profile only changes the TRANSCEIVER settings in station.toml (model, ports, PTT, sound cards, spectrum), through the same checked path as menu 3.2 (differences shown, confirmation, old version kept). Accounts, network, allowed bands and safety settings never change. Refused during a transmission.
Rights
session password asked

Going further

Files: /etc/trx-remote/profils/<nom>.toml. Each profile carries a format number. A profile from an older version is converted on loading when possible (a missing key takes its default value); otherwise, or if it comes from a newer version, it is refused with what to do: redo the configuration of that transceiver (menu 3.1) then save it again. The original file is never changed on loading.

3.4

Transceiver temperature thresholds (warning, cut-off)

What it is for
Transceiver temperature thresholds: first threshold (warning in the page and notification), second threshold (remote transmission cut and refused until back below the first threshold). 40 and 50 °C by default.
When
If your transceiver gets hot in normal use (continuous digital modes, for example) or for extra caution.
What it changes
The rig_temp_warn_c and rig_temp_cut_c keys of station.toml, through the same checked path as menu 3.2.
Rights
session password asked

Going further

No effect if the transceiver does not report its temperature through Hamlib (the case of the IC-7300MK2). The operator at the transceiver's microphone is never cut for this reason.

3.5

Top bar indicator (GNOME: station status at all times)

What it is for
Enables or disables the top bar indicator (GNOME desktop): a light to the left of the sound icon (green receive, red transmit, orange alert, grey station stopped, purple safe mode), the frequency or the transmit countdown, and on click the full status: transmission, frequency and filter, connected web clients, link with the transceiver, on-site operator, last cut, temperature, power supply, HF spectrum, DX Cluster, available update, version and identifier.
When
Once, after installation (then log out and log in again), to keep an eye on the station at all times.
What it changes
Only your desktop display. The indicator only READS the state published by the station: it cannot control anything.
Rights
no

Going further

Files read every second: /run/trx-remote/gateway-status.json, and in /var/lib/trx-remote/: safe_mode, cluster/status.json, update/latest.json, station-id. Extension installed in /usr/share/gnome-shell/extensions/trx-distant@rf-diy.com. The indicator menu also opens the web page, TRX Console and the dashboard.

4) Access

4.1

Pair a phone (Android app: address, fingerprint, QR code)

What it is for
Shows what you need to pair the Android app with this station: the address to enter, the allowed accounts, the certificate fingerprint (SHA-256, on two lines), then a QR code to scan with the app ("Scan the station QR code"): it fills in the address, username and fingerprint. If there are several addresses or accounts, the console asks which ones to put in the QR code (Enter = suggested choice). Neither the QR code nor the screen contains a password: the station does not know it in clear text, it is entered in the app.
When
When adding the station in the Android app, and after recreating the certificate (menu 3.1).
What it changes
Nothing: read-only.
Rights
no

Going further

Same display on the command line: trx-setup --output /etc/trx-remote/station.toml --empreinte. If the certificate can only be read by the station, the console reads it again with administrator rights. Station limited to this machine (loopback): no phone can connect to it, and the console says so. Behind an HTTPS proxy, the fingerprint to pin is the proxy certificate's (no QR code). The QR code is drawn for a dark-background terminal; the app also reads a light terminal. If it does not appear ("segno" package missing), reinstall the station (menu 6.3) or enter the fingerprint by hand.

4.2

Receive-only visitors (accounts, maximum number, connected)

What it is for
Manages receive-only visitors: accounts that listen to the station and see the operator's screen, without any command to the transceiver (no frequency, no mode, no transmission, no STOP). Here you set the maximum number of visitors (0 = listening closed on the station; otherwise the operator opens or closes listening from their page or the app, "Visitor listening" switch, closed by default), the "operator required" switch (visitors admitted only if an operator is connected, and disconnected after an adjustable wait, 60 s by default, if the operator loses the link), listening outside the station's bands (off by default: silence) and the HF spectrum rate for visitors (5 frames per second by default). Here you create, edit (nickname, password, enabled, end date) and delete visitor accounts, choose the nickname of operator accounts, disconnect a connected visitor, and reopen listening suspended by an overload.
When
Before a radio club demonstration, a training session or shared listening of a QSO; to remove a visitor's access (disable or delete their account).
What it changes
The accounts and the [access] section of station.toml, through the same checked path as menu 3.2 (differences shown, confirmation, old version kept; the file is rewritten in its standard form). The station reloads them on its own within a few seconds, without restarting: a disabled, expired or deleted account is disconnected at once. "Disconnect" does not touch station.toml.
Rights
session password asked

Going further

Other connected users never see an account's username, only its nickname (several accounts can share the same one); only an operator sees usernames and addresses. During a transmission, visitors hear the operator's voice (what goes to the transceiver); the SELCALL code is never shown to them. A visitor can only send two commands (read the state again, show or hide the HF spectrum): everything else is refused by the station, and beyond 20 refusals in one minute its connection is closed with an alert. Visitors have their own quota: they never take an operator's place. If the station is struggling (processor at 85 °C, 90 % loaded, gateway more than 100 ms late or memory almost full, for 10 s), visitors are disconnected with the exact cause; listening reopens on its own after 5 minutes clearly below, or by hand (choice 7) after 3 cuts in one hour. Thresholds: [access] overload_* (menu 3.2). Retransmitting what you receive to third parties is the operator's responsibility: see the remote access guide. Details: docs/visiteurs-cahier-des-charges.md.

5) Features

5.1

DX Cluster (followed spots, sources, test)

What it is for
DX Cluster settings: followed spots, sources (RBN, telnet servers, web), filters, source test.
When
To show spots on the spectrum and badges on the band buttons in the page.
What it changes
The Cluster section of station.toml; a restart is offered afterwards.
Rights
session password asked
5.2

Breizh Audio Box (pairing key, address, link test, log)

What it is for
Links the station to Breizh Audio Box, the voice processing that runs on a PC on the same local network: the operator's voice goes through Breizh before reaching the transceiver. Here you create the pairing key (shown only once, to copy into the "OpenRemoteTRX" tab of the Breizh settings together with the station address and port), set the IP address and UDP port of the Breizh PC, enable or disable routing through Breizh, run a link test without audio and read the log (connections, fallbacks, refusals). The current link state (ready, transmitting through Breizh, fallback, refused, round trip) is shown at the top.
When
When setting up Breizh, after reinstalling Breizh (new key), when the page or the app report a fallback, or to check the link before transmitting.
What it changes
The key: file breizh.key next to station.toml (never inside it), with the configuration's permissions. The address, port and activation: [breizh] section of station.toml, through the same checked path as menu 3.2 (differences shown, confirmation, old version kept); the station applies them on restart (offered). The test and the log change nothing.
Rights
session password asked

Going further

Safety: Breizh can never make the station transmit; the station keeps the PTT, the TOT, the audio gate and its limiter, and switches to direct at reduced gain (−6 dB by default) if Breizh stops answering for 100 ms, without cutting the transmission. Breizh's OpenRemoteTRX mode turns off its CAT. The microphone audio travels unencrypted on the local network: only a private IP address is accepted. On the Breizh PC, the firewall must let in UDP on the chosen port (47100 by default). The test sends a call and five PINGs, never audio; if the station is running with Breizh enabled, Breizh answers "busy" (it is already serving the gateway): this is normal, the state is at the top of the menu. Fine settings (delays, fallback gain, automatic return): [breizh], menu 3.2 and the station.toml reference. Details: docs/breizh-cahier-des-charges.md.

5.3

Group presence (nickname, groups of friends, invitations, sharing)

What it is for
Manages group presence: the station's nickname, the groups of friends (create, invite with a link and a QR code, join with a received invitation, leave, delete), and what the station shares in each group (frequency and mode, "On Air" only, or a short text; invisible). You also see who, in each group, is in a QSO, receiving, in the shack, away or offline.
When
To set up presence with friends equipped with openRemoteTRX, or when the page and the app are not at hand.
What it changes
The station's presence settings, stored separately in the state folder (not in station.toml); creating, inviting, joining and leaving go through the presence relay. Nothing touches the transceiver: a QSY to a friend is done from the page or the app.
Rights
session password asked

Going further

The console leaves its request for the "presence" module (file presence-request.json in the state folder, with sudo if needed) and reads its answer (presence/console-reply.json, erased after one minute: it may contain an invitation). The feature is enabled in station.toml (menu 3.2): [presence] enabled = true and "presence" in [modules] run, then restart the station. The relay only sees encrypted states: no frequency, no mode, no status. An invitation contains the group key: give it only to the invited person; it can be used only once and expires after 7 days. Details: docs/presence-cahier-des-charges.md.

6) Updates

6.1

Update TRX distant

What it is for
Update over the Internet: shows the new version, offers to see what changed (notes of EVERY version published since yours, newest first, page by page: Enter = next, q = stop there), then installs it after checking its signature. Up to date: offers an immediate new check on GitHub.
When
When a "NEW VERSION … AVAILABLE" box appears at the top of the console (yellow in a terminal) and menu 6.1 is marked "<== NEW VERSION". The check runs 2 minutes after the station starts, then every 24 h.
What it changes
Installs the new version next to the old one (kept for menu 6.2). station.toml and the certificates are kept. Refused while the transceiver is transmitting. You must type the version number to confirm.
Rights
session password asked
6.2

Go back to the previous version

What it is for
Goes back to the previous version, kept during the last update, without Internet.
When
If the new version causes problems.
What it changes
The active version. The configuration is kept.
Rights
session password asked
6.3

Install a version from a zip file (Desktop, Downloads)

What it is for
Installs a version from a trx-remote-debian-X.Y.Z.zip file placed on the Desktop, in Downloads or in the home folder.
When
Station without Internet, test version, or going back to a specific version.
What it changes
Like menu 6.1: new version next to the old one, configuration kept. An unsigned package asks you to type OUI then the version number.
Rights
session password asked

Going further

Dropping the zip is not enough: it must be installed here. Log: /var/log/trx-remote-install.log.

Advanced troubleshooting

Console header

The first line gives the installed version, the second the state (running, stopped, not configured yet). Once the station is configured come the address where it can be reached from the web page or the app (machine IP addresses and port; "this machine only" if it only listens locally), then the transceiver state: supply voltage and temperature, as read by the station ("—": value the transceiver does not provide; the IC-7300MK2, for example, does not report its temperature; "readings unavailable": station stopped). The last line gives the station identifier: a unique code created on first start, which makes it possible to match several reports from the same station. It is never sent anywhere automatically.

Useful files (Debian)

  • /etc/trx-remote/station.toml: configuration (edit through menu 3.2).
  • /var/lib/trx-remote/: station state (safe mode, memories, reports from the page, identifier station-id, DX Cluster).
  • /run/trx-remote/gateway-status.json: live state published by the gateway (read by the dashboard).
  • /opt/trx-remote/releases/: versions installed side by side; /opt/trx-remote/current points to the active version.
  • /var/log/trx-remote-install.log: log of installations and updates.

Readings from the transceiver (read-only)

For an Icom transceiver with a second CI-V port (spectrum), a raw dump of the settings, without any write, helps establish the real format of the answers. With the station stopped (menu 1.2), run:

/opt/trx-remote/current/venv/bin/python -m trxstation.devtools.civ_scope --port /dev/serial/by-id/<port-B> --reglages

The result is saved in a spectre-reglages-… folder: attach it to your request.

Reporting a problem

  1. In the web page: "Report a problem" section (text reviewed before sending).
  2. On the station: menu 2.3 (troubleshooting report), and if needed the result of menu 2.6.
  3. Describe what you were doing, what you expected and what happened, with the approximate time.
