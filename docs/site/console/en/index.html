TRX Console: user manual

TRX distant version 0.173.0

Language: Français · English · Deutsch · Español

TRX Console is the control panel of the TRX distant station, on the PC (or Raspberry Pi) connected to the transceiver. It is used to install and configure the station, start it, test it, update it and troubleshoot it. Open it from the applications menu ("TRX Console") or by typing trx-console in a terminal.

The menus are grouped by theme (Station, Transceiver and hardware, Transmit safety and alerts, Access and accounts, Features, Troubleshooting and assistance, Updates, Expert and preferences; numbers changed in 0.166.0): type the theme number then the menu number, or both at once, for example 4.1 to pair a phone. 0 changes the console language (français, English, Deutsch, Español).

Full screen (since version 0.170.0): on the left, the themes with their icon; arrows to choose, Enter to unfold a theme or open a menu; or digits, as in the text console (a digit opens a theme, then a digit opens its menu; 0 = language; r or Esc goes back to the themes; + expands all themes, - collapses them all; F5 refreshes); on the right, the help of the chosen menu; at the top, the station state. The opened menu runs as in the text console, then the screen comes back. It works over SSH and on Windows. trx-console --texte keeps the text console (numbered menus typed on the keyboard, described below); TRX_CONSOLE_SANS_ICONES=1 removes the icons.

Not sure about a menu? Type h followed by its number (for example h 4.1): without running anything, the console shows what the menu is for, when to use it and what it changes (the texts of this page).

It never transmits on its own: the only menus that can put the transceiver into transmit are the full test (menu 2.2, with confirmation at each step) and, of course, the station once started, controlled from the web page.

First deployment? Follow the steps below in order. Station already in service? Go straight to the menu reference. Helping with debugging? See the "Advanced troubleshooting" part.

First deployment, step by step

  1. Install the software

    On a Debian 12 or 13 PC with a desktop: unzip the package trx-remote-debian-X.Y.Z.zip into Downloads, open a terminal in the resulting folder and type:

    sudo bash install.sh

    Your session password is asked (nothing is shown while you type: this is normal). At the end, log out then log in again so that the new rights take effect.

    Coming from a Windows station? Put its station.toml file next to install.sh before starting the installation: accounts, bands and alerts will be carried over.

  2. Configure the station (menu 2.1)

    On first launch, TRX Console offers the wizard. It asks, in order: the transceiver model (Hamlib list), the CAT serial port, the PTT method, the sound cards (receive and transmit), the bands allowed for transmission, network access and the first account (username and password for the web page).

    The transceiver is queried read-only during the wizard: no transmission. Nothing is saved if you give up halfway.

  3. Check (menu 6.1)

    The diagnostic reviews everything without changing anything. Each line is OK, to watch or failed, with what to do. Fix the failures before going further (menu 8.1 to adjust the configuration, or run the wizard again).

  4. Test the transceiver (menu 2.2)

    First of all, the transceiver sound card must not be the PC's default sound device: on Debian, Settings > Sound, choose the PC speakers as output and its microphone as input (on Windows, Settings > System > Sound). Otherwise the desktop holds the card and its sounds go to the transceiver.

    Start with the receive-only test (choice 1): CAT link, received audio, frequency and mode changes, filter widths, spectrum. Only then does the full test (choice 2) check transmission: dummy load required, reduced power, confirmation asked at each step. The station is stopped during the test.

  5. Start (menu 1.1) and connect

    Menu 1.1 starts the station; run a diagnostic again (menu 6.1) a few seconds later. On the phone or another PC on the same network, open https://<adresse-de-la-station>:8443 and log in with the account created by the wizard. For access from outside, see the project's "Remote access" documentation.

The console menus

The main menu shows the themes: type the number of a theme then the number of one of its menus, or both at once (7.3); r goes back to the main menu, 0 changes the language, q quits. The old numbers 10 to 24 (single level, up to version 0.125.0) are still accepted for a while: the console gives the new one. Answers to questions (oui, non, OUI, EMETTRE...) ignore upper/lower case and accents. Password: the menu asks for your session password (sudo).

1) Station

1.1

Start or restart the station

What it is for
Starts (or restarts) the station: rigctld, gateway, supervisor.
When
After configuration, after a change, or if the web page no longer responds.
What it changes
The state of the services. The transceiver is always set back to receive at startup.
Rights
session password asked
1.2

Stop the station

What it is for
Stops the station.
When
Before plugging or unplugging the transceiver or the audio interface, or to use other software on the transceiver.
What it changes
The state of the services. The transceiver stays in receive.
Rights
session password asked
1.3

Dashboard (frequency, transmission, services)

What it is for
Live dashboard, in the terminal: frequency, mode, transmit or receive, connected clients, services, hardware, audio, log. It opens in a new tab or window (Windows Terminal, GNOME Terminal, tmux, screen): TRX Console stays open next to it; over SSH without tmux, it opens in the same terminal.
When
To watch the station on site, or during a test.
What it changes
Nothing, except one key: STOP TX forces receive. The dashboard can never make the transceiver transmit.
Rights
no
1.4

Leave safe mode

What it is for
Leaves safe mode. The supervisor puts the station into it after repeated failures: transceiver in receive, access cut.
When
Only after finding and fixing the cause (menus 6.1 and 6.2).
What it changes
Clears the stored safe mode and restarts the station.
Rights
session password asked

Going further

Safe mode survives restarts and fixes: it must be lifted explicitly here.

2) Transceiver and hardware

2.1

Configuration wizard

What it is for
Configuration wizard: transceiver, ports, PTT, sound cards, allowed bands, network access, accounts. Writes station.toml.
When
On first deployment, or to start over (new transceiver, audio interface or PC).
What it changes
station.toml (only if you go to the end). The station is stopped during the wizard then restarted on request.
Rights
session password asked

Going further

The transceiver is only queried read-only. A configuration imported from an old station (station.import.toml) is used as a starting point.

When a transceiver is added, the wizard asks whether replay of recordings is allowed (app: record the received audio then send it back on transmit, duration limited to the maximum transmit time minus 5 s). Default answer: no. Retransmitting a station's signal to third parties is generally forbidden in the amateur service: accept only if you need it and under your own responsibility ([safety] allow_replay).

2.2

Transceiver test (CAT, audio, PTT)

What it is for
Guided test of the real transceiver. Choice 1: receive only (CAT, received audio, tuning, filter widths, spectrum display). Choice 2: the same, then transmission.
When
After the wizard, after changing a cable or audio interface, or to qualify a new transceiver.
What it changes
Nothing in the configuration. Choice 2 makes the transceiver transmit: dummy load, reduced power, confirmation (type EMETTRE) at each step. The station is stopped during the test.
Rights
session password asked

Going further

The final summary of the test is shown on screen: copy it into your help request. Typed answers ignore upper/lower case and accents ("emettre", "Émettre" and "EMETTRE" are accepted).

2.3

Transceiver profiles (several rigs: save, load, delete)

What it is for
Transceiver profiles, for those who use several rigs in turn: save the configuration of the transceiver in service under a name ("IC-7300 home"), reload it later, or delete a profile. The profile in service is marked in the list.
When
After configuring and testing a transceiver (menus 2.1 and 2.2): save it. To change transceiver: plug it in, load its profile, and the station restarts with it.
What it changes
Loading a profile only changes the TRANSCEIVER settings in station.toml (model, ports, PTT, sound cards, spectrum), through the same checked path as menu 8.1 (differences shown, confirmation, old version kept). Accounts, network, allowed bands and safety settings never change. Refused during a transmission.
Rights
session password asked

Going further

Files: /etc/trx-remote/profils/<nom>.toml. Each profile carries a format number. A profile from an older version is converted on loading when possible (a missing key takes its default value); otherwise, or if it comes from a newer version, it is refused with what to do: redo the configuration of that transceiver (menu 2.1) then save it again. The original file is never changed on loading.

2.4

SDR receiver (search SDRs on USB, choose the station's one, settings)

What it is for
Prepares the station's SDR receiver (receive only, next to the TRX). It searches the SDRs plugged into every USB port, hubs included (SDRplay, RTL-SDR dongles), without opening any: type, serial number, location (port, hub) and state (free, held by a program, held by the kernel TV driver, this station's SDR). You choose the station SDR by its serial number (never by its port), then the width (2, 6 or 8 MHz), the antenna (A or B), the module's processor and memory limits, and you put it in service. An RTL-SDR dongle whose factory number is duplicated can get a new serial number (only one dongle plugged in, its memory backed up first, then unplug and plug it back).
When
When an SDR arrives; when an SDR changes port or a second SDR is plugged in (check the station keeps the right one); if the SDR uses too much on a small PC (width, limits).
What it changes
The [sdr] section of station.toml (and « sdr » in [modules] run when put in service), through the same checked path as menu 8.1; station restart offered. The search changes nothing and opens no SDR.
Rights
session password asked

Going further

An SDR that is held (for instance by another project) or whose serial number is duplicated (common on factory RTL-SDR dongles) is refused: the station would mistake one device for the other. The search also reports an SDR plugged into the same hub as the radio (to avoid). Same from the command line: trx-sdr --list (with sudo, the name of the program holding an RTL-SDR dongle is shown).

2.5

Transceiver and CAT link (model, port, speed, PTT, link test)

What it is for
Changes the transceiver and its link: Hamlib model (with the advised settings of a known transceiver), CAT serial port, speed, PTT method, then a read-only link test (no transmission). The station is stopped during the questions: the serial port must be free. The same questions as the matching part of the full wizard (menu 2.1), and only those: Enter keeps each current setting, the rest of the configuration is not touched.
When
New transceiver, serial port changed (other cable, other USB socket), speed changed in the transceiver menus, failed link test.
What it changes
The station configuration (station.toml), with administrator rights; the previous version is kept (station.toml.bak). Nothing is written if you give up. The station is restarted on request to take the change.
Rights
session password asked
2.6

Sound cards (audio received from the transceiver, voice to the transceiver)

What it is for
Chooses the sound cards: the one receiving the audio from the transceiver and the one sending the voice to it. The station is stopped during the questions: a busy card does not show in the list. The same questions as the matching part of the full wizard (menu 2.1), and only those: Enter keeps each current setting, the rest of the configuration is not touched.
When
No received audio, voice not going out, sound card changed or plugged into another socket.
What it changes
The station configuration (station.toml), with administrator rights; the previous version is kept (station.toml.bak). Nothing is written if you give up. The station is restarted on request to take the change.
Rights
session password asked
2.7

HF spectrum through the second CI-V port (Icom)

What it is for
Turns the HF spectrum (transceiver waterfall) on or off through the second serial port of an Icom set to CI-V. The port is checked with the station stopped; you confirm by typing YES that the USB SEND / USB Keying settings are done, because a badly set second port can key the transceiver. The same questions as the matching part of the full wizard (menu 2.1), and only those: Enter keeps each current setting, the rest of the configuration is not touched.
When
After setting the second CI-V port of the transceiver, or to turn the spectrum off. Not relevant for non-Icom transceivers.
What it changes
The station configuration (station.toml), with administrator rights; the previous version is kept (station.toml.bak). Nothing is written if you give up. The station is restarted on request to take the change.
Rights
session password asked

3) Transmit safety and alerts

3.1

Transceiver temperature thresholds (warning, cut-off)

What it is for
Transceiver temperature thresholds: first threshold (warning in the page and notification), second threshold (remote transmission cut and refused until back below the first threshold). 40 and 50 °C by default.
When
If your transceiver gets hot in normal use (continuous digital modes, for example) or for extra caution.
What it changes
The rig_temp_warn_c and rig_temp_cut_c keys of station.toml, through the same checked path as menu 8.1.
Rights
session password asked

Going further

No effect if the transceiver does not report its temperature through Hamlib (the case of the IC-7300MK2). The operator at the transceiver's microphone is never cut for this reason.

3.2

Bands allowed for transmission

What it is for
Decides who prevents transmitting outside your bands: the station (list of allowed bands, IARU region 1 starting points to check against your licence) or the transceiver itself. Empty list = receive only. The same questions as the matching part of the full wizard (menu 2.1), and only those: Enter keeps each current setting, the rest of the configuration is not touched.
When
At commissioning, after a licence change, or if the station refuses a transmission in an allowed band.
What it changes
The station configuration (station.toml), with administrator rights; the previous version is kept (station.toml.bak). Nothing is written if you give up. The station is restarted on request to take the change.
Rights
session password asked
3.3

Maximum power and maximum transmission time (TOT)

What it is for
Sets the transceiver maximum power (shown in watts by the page) and the maximum transmission time (TOT, 90 s by default, beep 10 s before cut-off, station ceiling). The supervisor cuts anyway beyond the absolute TOT. The same questions as the matching part of the full wizard (menu 2.1), and only those: Enter keeps each current setting, the rest of the configuration is not touched.
When
At commissioning, or to shorten or lengthen a transmission.
What it changes
The station configuration (station.toml), with administrator rights; the previous version is kept (station.toml.bak). Nothing is written if you give up. The station is restarted on request to take the change.
Rights
session password asked
3.4

Operator on site (transmitting with the transceiver microphone, absolute TOT)

What it is for
Sets what the station does when someone transmits with the transceiver microphone, in front of it. Shared station (default): such a transmission is only cut by the supervisor absolute TOT (135 s by default), or after the allowed time (300 s by default) when the operator presence is proven (they touched the transceiver just before). Otherwise any local transmission is cut at once. Remote transmission stays blocked during a local transmission and 2 minutes after.
When
At commissioning, if an operator uses the transceiver on site, or if the station goes into safe mode after transmissions with the transceiver microphone.
What it changes
The [supervisor] section of station.toml (allow_local_tx, tot_abs_s, local_tx_max_s), through the checked path of menu 8.1; the station restarts on request.
Rights
session password asked
3.5

Alerts on the phone (ntfy: address, language, test)

What it is for
Sets the alerts on the phone through ntfy: the address (a long secret topic: whoever knows it reads the alerts; the screen never shows it in full), the language (fr or en), the "Station in service" message (every N hours, silent), and sends a test alert (code ORT-8025) to check that everything arrives.
When
At commissioning (guide, part 6), after changing phone or ntfy subscription, or when no alert arrives.
What it changes
The [supervisor] section of station.toml (notify_url, notify_lang, alive_every_h), through the checked path of menu 8.1; the test writes nothing.
Rights
session password asked

4) Access and accounts

4.1

Pair a phone (Android app: address, fingerprint, QR code)

What it is for
Shows what you need to pair the Android app with this station: the address to enter, the allowed accounts, the certificate fingerprint (SHA-256, on two lines), then a QR code to scan with the app ("Scan the station QR code"): it fills in the address, username and fingerprint. If there are several addresses or accounts, the console asks which ones to put in the QR code (Enter = suggested choice). Neither the QR code nor the screen contains a password: the station does not know it in clear text, it is entered in the app.
When
When adding the station in the Android app, and after recreating the certificate (menu 2.1).
What it changes
Nothing: read-only.
Rights
no

Going further

Same display on the command line: trx-setup --output /etc/trx-remote/station.toml --empreinte. If the certificate can only be read by the station, the console reads it again with administrator rights. Station limited to this machine (loopback): no phone can connect to it, and the console says so. Behind an HTTPS proxy, the fingerprint to pin is the proxy certificate's (no QR code). The QR code is drawn for a dark-background terminal; the app also reads a light terminal. If it does not appear ("segno" package missing), reinstall the station (menu 7.3) or enter the fingerprint by hand.

4.2

Receive-only visitors (accounts, maximum number, connected)

What it is for
Manages receive-only visitors: accounts that listen to the station and see the operator's screen, without any command to the transceiver (no frequency, no mode, no transmission, no STOP). Here you set the maximum number of visitors (0 = listening closed on the station; otherwise the operator opens or closes listening from their page or the app, "Visitor listening" switch, closed by default), the "operator required" switch (visitors admitted only if an operator is connected, and disconnected after an adjustable wait, 60 s by default, if the operator loses the link), listening outside the station's bands (off by default: silence) and the HF spectrum rate for visitors (5 frames per second by default). Here you create, edit (nickname, password, enabled, end date) and delete visitor accounts, disconnect a connected visitor, and reopen listening suspended by an overload.
When
Before a radio club demonstration, a training session or shared listening of a QSO; to remove a visitor's access (disable or delete their account).
What it changes
The accounts and the [access] section of station.toml, through the same checked path as menu 8.1 (differences shown, confirmation, old version kept; the file is rewritten in its standard form). The station reloads them on its own within a few seconds, without restarting: a disabled, expired or deleted account is disconnected at once. "Disconnect" does not touch station.toml.
Rights
session password asked

Going further

Other connected users never see an account's username, only its nickname (several accounts can share the same one); only an operator sees usernames and addresses. During a transmission, visitors hear the operator's voice (what goes to the transceiver); the SELCALL code is never shown to them. A visitor can only send two commands (read the state again, show or hide the HF spectrum): everything else is refused by the station, and beyond 20 refusals in one minute its connection is closed with an alert. Visitors have their own quota: they never take an operator's place. If the station is struggling (processor at 85 °C, 90 % loaded, gateway more than 100 ms late or memory almost full, for 10 s), visitors are disconnected with the exact cause; listening reopens on its own after 5 minutes clearly below, or by hand (choice 6) after 3 cuts in one hour. Thresholds: [access] overload_* (menu 8.1). Retransmitting what you receive to third parties is the operator's responsibility: see the remote access guide. Details: docs/visiteurs-cahier-des-charges.md.

4.3

Operator accounts (one per device: add, password, disable, delete)

What it is for
Manages the operator accounts, the ones that control the transceiver and transmit. The rule: one account per device (PC, phone, tablet), named after the device (PC, S25…). The same account opened on a second device closes the first device's connection and cuts its transmission. Here you add an account (password typed or generated, then the pairing QR code of that account for the Android app), change a password, disable or re-enable an account, choose its nickname (shown to other connected users) and delete it. Connected accounts are marked.
When
When a new device arrives (phone, tablet, second PC); after a phone is lost or stolen (disable its account); to change a password.
What it changes
The [[clients]] accounts of station.toml, through the same checked path as menu 8.1 (differences shown, confirmation, old version kept; the file is rewritten in its standard form). The station reloads them by itself within a few seconds, without restarting: the connection of an account that is disabled, deleted or whose password changed is closed at once (its transmission is cut).
Rights
session password asked

Going further

The last active operator account can be neither disabled nor deleted: the station could no longer be controlled. The password is never stored in clear (scrypt hash only): a forgotten password is replaced. One account per device also tells who is transmitting (the station refuses transmission to the others meanwhile) and lets you remove a single device. Same thing on the command line: trx-setup --output /etc/trx-remote/station.toml --add-client NAME or --set-password NAME. Visitor accounts (receive only) are in menu 4.2.

4.4

Station certificate (authority to install: no more warning, password remembered)

What it is for
Shows the station's HTTPS certificate (names and addresses, expiry, origin) and remakes it signed by the station authority. Once this authority is installed on a device (PC, phone), the browser no longer warns and can remember the password (Chrome refuses to save it with an unrecognised certificate). The download link of the authority is shown; the page offers it too.
When
Once, to stop the browser warning and get the saved password; to add a name or address (VPN, local name) to the certificate.
What it changes
The files of the station's tls folder (authority created if needed, gateway certificate remade) and [network] tls_cert / tls_key if needed. The fingerprint changes: the Android app must be paired again (menu 4.1). The station must restart to use it (offered).
Rights
session password asked

Going further

The authority is limited by name constraints to private addresses (local network, VPN) and to the station's names: even if stolen, its key could not impersonate another site on the devices that installed it. Its key stays on the station, readable by the administrator only. It is reused as long as its constraints cover the requested names; a new DNS name needs a new authority, to reinstall. Same from the command line: trx-setup --output /etc/trx-remote/station.toml --autorite-station [NAMES…].

4.5

Network access (listening address, HTTPS, certificate)

What it is for
Chooses where the station can be reached from: this machine only, or the local network and VPN over HTTPS with a certificate signed by the station authority. A new certificate means pairing the app again (menu 4.1). The same questions as the matching part of the full wizard (menu 2.1), and only those: Enter keeps each current setting, the rest of the configuration is not touched.
When
At commissioning, after the PC address changed, or to open the station to the phone.
What it changes
The station configuration (station.toml), with administrator rights; the previous version is kept (station.toml.bak). Nothing is written if you give up. The station is restarted on request to take the change.
Rights
session password asked

5) Features

5.1

DX Cluster (followed spots, sources, test)

What it is for
DX Cluster settings: followed spots, sources (RBN, telnet servers, web), filters, source test.
When
To show spots on the spectrum and badges on the band buttons in the page.
What it changes
The Cluster section of station.toml; a restart is offered afterwards.
Rights
session password asked
5.2

Breizh Audio Box (pairing key, address, link test, log)

What it is for
Links the station to Breizh Audio Box, the voice processing that runs on a PC on the same local network: the operator's voice goes through Breizh before reaching the transceiver. Here you create the pairing key (shown only once, to copy into the "OpenRemoteTRX" tab of the Breizh settings together with the station address and port), set the IP address and UDP port of the Breizh PC, enable or disable routing through Breizh, run a link test without audio and read the log (connections, fallbacks, refusals). The current link state (ready, transmitting through Breizh, fallback, refused, round trip) is shown at the top.
When
When setting up Breizh, after reinstalling Breizh (new key), when the page or the app report a fallback, or to check the link before transmitting.
What it changes
The key: file breizh.key next to station.toml (never inside it), with the configuration's permissions. The address, port and activation: [breizh] section of station.toml, through the same checked path as menu 8.1 (differences shown, confirmation, old version kept); the station applies them on restart (offered). The test and the log change nothing.
Rights
session password asked

Going further

Safety: Breizh can never make the station transmit; the station keeps the PTT, the TOT, the audio gate and its limiter, and switches to direct at reduced gain (−6 dB by default) if Breizh stops answering for 100 ms, without cutting the transmission. Breizh's OpenRemoteTRX mode turns off its CAT. The microphone audio travels unencrypted on the local network: only a private IP address is accepted. On the Breizh PC, the firewall must let in UDP on the chosen port (47100 by default). The test sends a call and five PINGs, never audio; if the station is running with Breizh enabled, Breizh answers "busy" (it is already serving the gateway): this is normal, the state is at the top of the menu. Fine settings (delays, fallback gain, automatic return): [breizh], menu 8.1 and the station.toml reference. Details: docs/breizh-cahier-des-charges.md.

5.3

Group presence (nickname, groups of friends, invitations, sharing)

What it is for
Manages group presence: the station's nickname, the groups of friends (create, invite with a link and a QR code, join with a received invitation, leave, delete), and what the station shares in each group (frequency and mode, "On Air" only, or a short text; invisible). You also see who, in each group, is in a QSO, receiving, in the shack, away or offline.
When
To set up presence with friends equipped with openRemoteTRX, or when the page and the app are not at hand.
What it changes
The station's presence settings, stored separately in the state folder (not in station.toml); creating, inviting, joining and leaving go through the presence relay. Nothing touches the transceiver: a QSY to a friend is done from the page or the app.
Rights
session password asked

Going further

The console leaves its request for the "presence" module (file presence-request.json in the state folder, with sudo if needed) and reads its answer (presence/console-reply.json, erased after one minute: it may contain an invitation). The feature is enabled in station.toml (menu 8.1): [presence] enabled = true and "presence" in [modules] run, then restart the station. The relay only sees encrypted states: no frequency, no mode, no status. An invitation contains the group key: give it only to the invited person; it can be used only once and expires after 7 days. Details: docs/presence-cahier-des-charges.md.

5.4

Last antenna SWR measurement (read-only)

What it is for
Shows the last antenna SWR measurement stored on the station: date, power, mode, range, and the SWR of each point with a small bar ("HIGH" above 2), the best point and any transceiver settings that may not have been restored. Read-only: the console never starts a measurement (a tool can only cut a transmission); the measurement is started from the page or the app.
When
To find a measurement made remotely, compare it with a new one, or check that a transceiver setting was properly restored after an interrupted measurement.
What it changes
Nothing.
Rights
no

Going further

File read: swr.json in the station state folder (last choices of each account, SWR reading time calibrated per transceiver model, last measurement). Station settings: [swr] section of station.toml (menu 8.1: enabled, power ceiling max_power_pct, max_points, point_tx_max_s). Details: docs/tos-cahier-des-charges.md.

5.5

Features in service (switches)

What it is for
Turns each station feature on or off by its number: DX Cluster, FreeDV, FreeDV activity, SELCALL, group presence, monitoring, SDR, Breizh Audio Box, network probe, SWR measurement. The switch sets both the feature and the start of its module. A feature that needs other settings is refused with the menu where to make them.
When
To try or remove a feature without editing station.toml.
What it changes
The feature sections (enabled) and [modules] run of station.toml, through the checked path of menu 8.1; the station restarts on request.
Rights
session password asked

6) Troubleshooting and assistance

6.1

Full diagnostic

What it is for
Full check of the station, read-only: system, software, configuration, hardware (serial ports, sound cards), services, HF spectrum, DX Cluster, network access and updates. At the end, three "Station modes" lines: Breizh Audio Box (enabled or not, link state), visitor listening (open or closed, maximum number) and visitor accounts (nickname, disabled, expired), without any secret.
When
After installation, after every change, and as a first reflex whenever something is wrong.
What it changes
Nothing. No command to the transceiver, no transmission.
Rights
no

Going further

Same result without the menu: trx-console --diagnostic (non-zero exit code on failure, usable in a script).

6.2

Station log

What it is for
Shows the last 80 lines of the station services log.
When
When the diagnostic reports a failed service, or to understand why a transmission was cut.
What it changes

6.4

Network quality (links, dropouts, statistics, export, erase)

What it is for
Shows the quality of the links between the station and the connected phones or browsers: for each one, the state (good, fair, weak, dropout), the network type, the loss and the round-trip time; the state of the station probes towards the router and the Internet; the last dropout with its probable segment; and the "VPN profile probably shared" warning when two devices seem to use the same VPN profile. Here you read the summary of the last 24 hours or the last 30 days (dropouts, duration, segments, most affected hours, per network), create an anonymous export on the Desktop for the development team, and can erase everything.
When
When the link often drops (in the car, on 4G, through a VPN), to find out whether it is the phone, the mobile network, the tunnel, the router or the station; before asking for help (export).
What it changes
Nothing, except "Erase everything" (confirm by typing EFFACER): the station's network history (dropouts, statistics, devices seen). The indicator thresholds chosen in the page or the app are kept. The export is a zip file on the Desktop.
Rights
session password asked

Going further

The station sends a one-second heartbeat to each connected client and waits for its echo; three heartbeats without an answer make a dropout. After each dropout, it combines its own probes (router, Internet, ping or else TCP), the measurements sent by the client (including HTTPS access to the station during the dropout) and the regularity of the dropouts to tell which segment probably failed; it is a probability, never a certainty. Two devices on the same VPN profile steal the link from each other every 15 to 30 s: one profile per device. The probe only measures: it never acts on transmission. Files: netprobe folder in the state folder (7-day log, 30-day dropouts and statistics). Same summary on the command line: trx-netreport (--jours 30, --export FICHIER). Settings: [netprobe] section of station.toml (menu 8.1). "Erase everything" asks for sudo: the files belong to the station account. Details: docs/netprobe-cahier-des-charges.md.

6.5

Station-to-station monitoring (help an operator in trouble, or get help)

What it is for
Help an operator in trouble, or get help, without VPN or open port. The helper creates a 10-character code and reads it out; the helped operator types it; both compare 6 digits by voice. The helped operator chooses what is sent (essential, or diagnostic with the rig state; frequency and mode only if they wish). You see the latest news and error codes of each followed station, request or accept assistance mode (news every 30 seconds, for a chosen duration), pause and end a link. The helper can also ask for the troubleshooting report (the one of menu 6.3, fully masked); the helped operator accepts or sends it on their own (choice 10), and the helper copies it to their Desktop. The helper gets an alert on their phone (their station's ntfy) when a followed station stops sending news, when it comes back, or when it reports a critical event.
When
When an operator needs help with their station, or when you ask for help: on the phone with the helper, menu open on both sides.
What it changes
Links, nickname and what is sent, stored separately in the state folder (not in station.toml); everything goes encrypted through the relay. Nothing touches the rig: the helping station can only read and ASK, never command; the helped operator can stop everything at any time.
Rights
session password asked

Going further

The console leaves its request for the "monlink" module (file monlink-request.json in the state folder, with sudo if needed) and reads its answer (monlink/console-reply.json, deleted after one minute). The feature is enabled in station.toml (menu 8.1): [monitor_link] enabled = true and "monlink" in [modules] run, then restart the station. Everything sent is masked (passwords, addresses, serial numbers, computer name). The code works once and expires after 15 minutes; different digits = link refused. Details: docs/cdc-monitoring.md § 17.

8.3

Transceiver qualification (expert: never-tested transceiver)

What it is for
Transceiver qualification with trx-qualif, for an expert who wants to go as far as possible with a transceiver never tested but known to Hamlib. Choice 1: test plan and Hamlib inconsistencies, without touching the transceiver. Choice 2: exploration without transmission (everything Hamlib declares is read and compared with the transceiver's answers). Choice 3: the same, read-only. Choice 4: qualification without transmission. Choice 5: full qualification.
When
Before using a new transceiver model, or to prepare a report for the Hamlib developers.
What it changes
Nothing in the configuration. Choices 2 and 4 change the frequency and a few receive settings of the transceiver, then put them back; the exploration never changes the mode. Only choice 5 transmits (dummy load, confirmation EMETTRE at each step). The station is stopped during the test.
Rights
session password asked

Going further

Reports in the station state folder (qualifications/): exploration.json, constats.txt, drafts fiche-poste.md and rapport-hamlib.md (in English), trace of every command (cat_trace.log). The exploration never sends a PTT command and stops at once if the transceiver starts transmitting (its own microphone). Filter widths are only tried with trx-qualif --filtres: on an Icom, every width sent is written into a FIL1/2/3 preset.

Advanced troubleshooting

Console header

The first line gives the installed version, the second the state (running, stopped, not configured yet). Once the station is configured come the address where it can be reached from the web page or the app (machine IP addresses and port; "this machine only" if it only listens locally), then the transceiver state: supply voltage and temperature, as read by the station ("—": value the transceiver does not provide; the IC-7300MK2, for example, does not report its temperature; "readings unavailable": station stopped). The last line gives the station identifier: a unique code created on first start, which makes it possible to match several reports from the same station. It is never sent anywhere automatically.

Useful files (Debian)

  • /etc/trx-remote/station.toml: configuration (edit through menu 8.1).
  • /var/lib/trx-remote/: station state (safe mode, memories, reports from the page, identifier station-id, DX Cluster).
  • /run/trx-remote/gateway-status.json: live state published by the gateway (read by the dashboard).
  • /opt/trx-remote/releases/: versions installed side by side; /opt/trx-remote/current points to the active version.
  • /var/log/trx-remote-install.log: log of installations and updates.

Readings from the transceiver (read-only)

For an Icom transceiver with a second CI-V port (spectrum), a raw dump of the settings, without any write, helps establish the real format of the answers. With the station stopped (menu 1.2), run:

/opt/trx-remote/current/venv/bin/python -m trxstation.devtools.civ_scope --port /dev/serial/by-id/<port-B> --reglages

The result is saved in a spectre-reglages-… folder: attach it to your request.

Reporting a problem

  2. On the station: menu 6.3 (troubleshooting report), and if needed the result of menu 8.2.
  3. Describe what you were doing, what you expected and what happened, with the approximate time.
